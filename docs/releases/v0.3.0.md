# NEXUS v0.3.0 — indexed files and folders

**Status:** historical release candidate; packaging was verified, with desktop and
installation acceptance outstanding. Code date: 2026-11-14.
The `v0.3.0` tag identifies
[commit 54da00e](https://github.com/ishanpati/Nexus/commit/54da00eae24a244834e56dc00c4ddae99b72ffed);
package metadata is 0.3.0. No public release download is advertised here.

## What improved

- Type `f ` followed by a literal file/folder name or path fragment to search
  Everything's local index without mixing those results with app search.
- Browse highlighted results in batches, with up to 100 matches. Debouncing and
  stale-response protection keep older queries from replacing newer results.
- Open files with their default application, open folders in Explorer, or use
  Ctrl+Enter/Show to reveal a selected result.
- See distinct errors for missing ES, unavailable Everything, timeouts, and empty
  results, with a retry path.
- Sensitive file types require a separate confirmation; Escape cancels the prompt.
  Rust rejects invalid paths and reserved Windows device names.

## Installation and upgrades

Target: Windows 11 x64 and WebView2. For file search only, install and run the
Everything desktop client plus its separate ES tool; ES 1.1.0.38 was verified.
App search still works without them. See [Everything setup](../features/file-search/FILE_SEARCH.md#setup).

The report records locally built `nexus_0.3.0_x64-setup.exe` and
`nexus_0.3.0_x64_en-US.msi`. They are unsigned; offline installation requires
WebView2 already installed. Choose one installer format and close NEXUS first.
Installer identity remains `com.nexus.launcher`; actual upgrade/uninstall was
not verified. No workflow database is introduced by this version.

## Known limitations and evidence

Search covers indexed names/paths, not contents, named Everything instances, or
advanced Everything syntax. Entries may be stale or inaccessible. There are no
file mutations, signing, tray icon, or automatic updates.

[The verification report](../verification/RELEASE_VERIFICATION.md) records real
Everything diagnostics, automated checks, packaging, and standalone process
startup. That startup check does not prove complete GUI interaction. Fresh
installation, upgrade, uninstall, and disconnected runtime remained pending.
[Historical checksums](RELEASE_SHA256.txt) identify the report's original builds,
not every later file bearing these filenames.
