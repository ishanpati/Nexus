## Changes

Installed catalog apps use the existing Shell/packaged launch mechanisms plus a
shared bounded foreground handoff. Shortcut arguments and working directories stay
Shell-controlled. The command bar and saved workflow app.launch action reuse the
same native implementation. Success distinguishes Windows acceptance from window
detection and point-in-time foreground verification; activation failure does not
fail an accepted workflow action. Minimized targets are restored without forcing
maximization, and denied activation can flash the selected taskbar button.

The audit tightens admission-time stale intent, ownership of launcher hiding after
Shell changes focus, activation timeout classification, DWM-cloaked filtering and
argument/profile window association. Enter consumes the selected app/workflow row
once after key release. No title matching, focus tricks, new runtime service, cloud
API, paid dependency, or unrelated feature is introduced.

## Install and upgrade

Windows 11 x64 and Microsoft Edge WebView2 Runtime are required. Candidate names:

- nexus_0.5.1_x64-setup.exe (NSIS)
- nexus_0.5.1_x64_en-US.msi (MSI)

These are local candidate artifacts, not download links. Use the audit's exact
paths and [SHA-256 manifest](V051_SHA256.txt) for this local build. Install one format. Unsigned packages may
trigger Windows warnings. WebView2 must already be installed for offline setup;
otherwise setup can require a download. No Vite server, Node, Rust, API key or model
is required to run the packaged app.

Close NEXUS and back up the complete stopped data directory before upgrading.
The installer identifier remains com.nexus.launcher. Workflow document format and
SQLite user_version remain 1; data stays in
%LOCALAPPDATA%\com.nexus.launcher\workflows.sqlite3. Development and installed builds
share this directory. Leave NSIS's app-data deletion checkbox unchecked. See
[backup and restore](../USER_GUIDE.md#workflow-data-and-backup).

## Limits and acceptance

Windows foreground restrictions remain authoritative. Unknown or ambiguous native
identity, argument-driven profiles/hosts, unusual or hosted top-level windows,
windowless apps, or startup beyond the discovery budget can leave activation
unverified. New user input deliberately suppresses extra activation. Shell and the
target app can independently change focus later; cancellation cannot undo an
accepted native launch. Workflow steps remain sequential and stop on real errors.

The audit separately records closed/running/minimized/slow apps, Store apps,
workflow cancellation, global shortcut/Escape/Studio, installed use, offline use,
and upgrade checks as executed or pending. Existing security caveats (unsigned
installers, disabled CSP, plaintext workflow data) remain; this patch does not
establish broader release acceptance or authorize publication.
