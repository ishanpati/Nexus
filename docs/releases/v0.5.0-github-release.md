# NEXUS v0.5.0 — Workflow Studio (release candidate)

> **DRAFT — publication on hold.** Desktop, installation, upgrade/data-preservation,
> and final artifact/checksum acceptance are incomplete. This text is prepared for
> GitHub Releases; no GitHub Release is being published by this documentation task.

NEXUS v0.5.0 adds Workflow Studio to the local-first Windows command bar. Build a
routine from supported actions, save it on your PC, and launch it by name without
scripts, API keys, subscriptions, or an AI model.

## Highlights

- **Create and edit workflows:** name a routine, add descriptions/aliases, choose
  actions, configure parameters, and reorder steps in a separate Studio window.
- **Manage saved routines:** search the saved list, rename or repair workflows,
  and confirm deletion. Save / Discard / Cancel protects unsaved changes.
- **Launch from the bar:** type `w ` to browse, or search by partial name or alias;
  activate the selected result to start it.
- **See what happened:** sequential execution shows step progress, completion,
  failures, and cancellation. Closing progress or hiding the launcher leaves runs active.
- **Keep approval explicit:** workflow lock/sleep steps must be final and need fresh
  approval for every run. Saving a routine does not approve a sensitive operation.

Actions can launch installed catalog apps, open documents/folders, adjust audio,
open supported Windows Settings pages, lock, or sleep. Executable/script-like
workflow file steps are refused. Existing application search, Everything file
search, and Windows controls remain available.

## Requirements and installation

- **Windows 11 x64** and **Microsoft Edge WebView2 Runtime**.
- **File search only:** Everything desktop plus its separate ES command-line tool
  (ES 1.1.0.38 verified). Everything must be running in your Windows session.
- Audio needs an enabled output device and Windows Audio service; Settings/power
  behavior depends on hardware and Windows policy.

Public installers are not available yet. The locally built
candidate filenames are `nexus_0.5.0_x64-setup.exe` and
`nexus_0.5.0_x64_en-US.msi`; they are not approved publication assets yet.
Once an exact artifact set has passed acceptance, provide its matching SHA-256
manifest and attach those installers before authorizing publication.

Close NEXUS and back up workflow data first, then install one format. The
installers are **unsigned**, so Windows may show an unknown publisher. Preinstall
WebView2 for offline setup; otherwise setup can download it. End users do not need
Node.js, Rust, a source checkout, a development server, or a cloud service.

## Upgrading and protecting workflows

Workflows are plaintext local data at
`%LOCALAPPDATA%\com.nexus.launcher\workflows.sqlite3`. Development and installed
builds with the default identifier share that directory. Schema/document version
1 and the application identifier are unchanged, but installer upgrade preservation
still needs acceptance testing.

Fully stop NEXUS and copy the complete data directory, including any SQLite
sidecars, before upgrading, reinstalling, or uninstalling. Keep a pre-upgrade
backup and leave the NSIS app-data deletion checkbox unchecked. Never replace a
live database. Moving to another PC may require repairing app/file references.

## Known limitations and acceptance status

- **Release acceptance remains pending:** installation, upgrade/uninstall,
  disconnected desktop use, and the full Windows 11 regression/performance checklist.
- Runs are sequential and session-only. There is no rollback, crash resume, delay,
  parallel-step facility, scripting, custom executable arguments, or app readiness wait.
- Cancellation stops future steps; completed actions are not undone and in-flight
  Windows requests cannot be recalled. Activation success is Windows acceptance.
- Workflow storage has no encryption, sync, automatic backup, or export/import UI.
  CSP remains disabled. File associations, device availability, hardware, and
  Windows policy continue to affect native operations.
- Existing Stage G checksums belong to an earlier build. They do not match the
  inspected local rebuilds and must not be supplied as hashes for them.
