# NEXUS v0.4.0 — Windows controls

**Status:** historical release candidate; installers were built, but installation
and full desktop acceptance were incomplete. Code date: 2026-11-15.
The `v0.4.0` tag identifies
[commit e8c4a35](https://github.com/ishanpati/Nexus/commit/e8c4a35f1ad700157d8ce943cc0e3bf79a3fe607);
package metadata is 0.4.0. No public release download is advertised here.

## What improved

- Set volume, make relative adjustments, mute/unmute, and read audio state.
  Successful volume/mute changes show a brief NEXUS overlay without taking focus.
- Open Sound, Wi-Fi, Bluetooth, and Display Settings; lock directly or request sleep
  through a separate confirmation dialog.
- Discover supported commands through aliases, typed usage guidance, and status hints.
- Successful actions clear input and hide the bar; failures preserve the query.
  Clicks and Enter share selection dispatch, including partial fixed-command results.
- App discovery, file search/ranking, icons, the global shortcut, and monitor
  placement remain available.

## Installation and upgrades

Target: Windows 11 x64 with WebView2. Audio needs an enabled output device and
Windows Audio service; Settings destinations and sleep depend on device/policy
support. Everything desktop and ES remain optional for file search only.

The report records `nexus_0.4.0_x64-setup.exe` and `nexus_0.4.0_x64_en-US.msi`
as local unsigned outputs. Choose one format, close NEXUS first, and preinstall
WebView2 for offline setup. Installer identity remains `com.nexus.launcher`.
Upgrade preservation has not been established by building those files. Workflows
are introduced later, but newer development builds can already share local data;
follow the [backup precautions](README.md#installation-and-upgrades).

## Safety, limitations, and evidence

Only allowlisted Settings pages are accepted. Sleep needs fresh, expiring,
single-use confirmation; standalone lock does not use the workflow approval UI
introduced in v0.5. The overlay is NEXUS feedback, not Windows' media-key flyout.

[The verification report](../verification/V04_VERIFICATION.md) records automated
tests, real read-only app/file diagnostics, an opt-in audio round-trip with state
restoration, and both installer builds. Lock/sleep transitions, install/upgrade,
device switching, and broader hardware/policy behavior remain manual. Windows
request acceptance does not establish a completed transition.
