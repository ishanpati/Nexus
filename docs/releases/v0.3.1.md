# NEXUS v0.3.1 — better file-search relevance

**Status:** historical development milestone. Code date: 2026-11-14.
The `v0.3.1` tag identifies
[commit f58fb9c](https://github.com/ishanpati/Nexus/commit/f58fb9ce0a3b748778f483b4c7bf7d64744e074b).
Package metadata remains **0.3.0**; the ranking task produced no new installer.

## What improved

- Exact filenames, filename stems, and folder names appear before weaker path matches.
- Separate folder/file candidate pools reduce crowding by descendant paths.
- Desktop, Documents, and Downloads locations use Windows Known Folder resolution,
  including OneDrive redirection. Cache/build locations receive lower preference.
- Recent successful file opens and optional `NEXUS_PROJECT_DIRS` roots provide
  small tie-breakers within a match tier; they cannot override a better text match.

Live diagnostics reproduced and improved two cases: finding the NEXUS project
folder and preferring a directly stored Desktop file over cache copies. Local
timing samples in the report are not release performance guarantees.

## Requirements and limitations

Windows 11 x64, WebView2, Everything desktop, and ES requirements are unchanged
from [v0.3.0](v0.3.0.md). The default file-opening and confirmation policies remain.
No workflow storage exists at this stage.

Candidate pools are finite: not every equally named copy is guaranteed to be
retrieved. File fuzzy search is not implemented, and sparse queries can require
more ES calls. New installer, live file-open history, and complete interactive
regression were not verified for the ranking task.
