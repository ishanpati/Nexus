## Highlights

- **Create a routine:** open `create workflow`, give it a name, description, and
  optional aliases, then combine supported actions in an ordered list.
- **Edit and manage:** reopen saved workflows, change parameters, reorder steps,
  rename, filter, or explicitly confirm deletion. Save / Discard / Cancel protects
  unsaved changes during navigation, Studio close, and launcher quit.
- **Save locally:** workflow definitions persist in SQLite on your PC, with stable
  identities and checks against stale edits. Missing apps, paths, or obsolete actions
  remain visible for repair rather than disappearing silently.
- **Find and launch:** type `w ` to browse, or `w ` followed by a name/alias fragment.
  Enter or a click runs the selected saved workflow. Typing only searches.
- **Follow execution:** steps run sequentially, with progress, completed results,
  errors, and cancellation through Workflow runs. A failure stops later steps.
  Hiding the launcher or closing progress leaves the run active.
- **Approve sensitive actions:** workflow lock/sleep must be last and require a fresh
  explicit decision for each run. Approval expires and cannot be reused. Saving a
  workflow grants no permission to perform a sensitive action.

Supported workflow actions launch catalog applications, open documents/folders,
set or adjust volume, mute/unmute, open allowlisted Settings pages, lock, or sleep.
Workflow file steps reject executable, script, shortcut, installer, macro-capable,
and unknown file types. Existing app/file search and Windows commands remain available.

The candidate also fixes launcher close destroying the shortcut's window while
auxiliary windows survived, and aligns workflow save validation with the runner's
sensitive-file restrictions. Those Stage G fixes have automated coverage;
their final native acceptance is still pending.

## Requirements and installation

Target: **Windows 11 x64** with **Microsoft Edge WebView2 Runtime**. Audio controls
need a working output device and Windows Audio service. Everything desktop plus
the separate ES tool are optional for file search; ES 1.1.0.38 was verified.
Run Everything in your Windows session and follow the [ES setup guide](../features/file-search/FILE_SEARCH.md#setup).

Local candidate output filenames are `nexus_0.5.0_x64-setup.exe` and
`nexus_0.5.0_x64_en-US.msi`. These names are not download links. No public assets
were listed when the release inventory was reviewed on 2026-11-16.

If given an approved candidate with matching checksums, close NEXUS, back up data,
and choose one installer format. Installers are **unsigned**, so Windows can show
an unknown-publisher warning. Setup can download missing WebView2; install it
beforehand for offline setup. Installed use requires no Node, Rust, Vite, API key,
AI model, or cloud service. See the [user guide](../USER_GUIDE.md#install-and-run).

## Upgrade and local data

Workflow data remains at `%LOCALAPPDATA%\com.nexus.launcher\workflows.sqlite3`.
Installer identity stays `com.nexus.launcher`; SQLite `user_version` and workflow
document format stay 1. These match v0.5 development storage, not a newly claimed
workflow database in the earlier v0.4 product. Development and installed builds
share this location by default.

Fully stop every NEXUS instance and back up the complete data directory, including
any SQLite sidecars, before upgrade/reinstall/uninstall. Retain a pre-upgrade copy;
never overwrite a live database. Leave NSIS's app-data deletion checkbox unchecked
to preserve workflows. Unknown database versions fail without automatic reset,
but actual installer upgrade and data preservation remain unverified.
See [backup and restore](../USER_GUIDE.md#workflow-data-and-backup).

## Known limitations

- Run history and approvals last only for the current process. No rollback,
  crash resume, delays, parallel steps, scripts, arbitrary executable arguments,
  recursive workflows, or application-readiness waits are provided.
- Cancellation prevents future actions; an admitted Windows request cannot be
  recalled. Launch success means Windows accepted activation, not that an app is ready.
- Workflow data is plaintext with no encryption, sync, export/import UI, or automatic
  backup. Moving between PCs can require repairing app/path references.
- File search covers indexed names/paths with finite retrieval limits. Windows
  associations, missing devices, hardware, policy, and blocked native calls retain
  their existing limitations.
- CSP remains disabled, installers are unsigned, and installed startup/performance,
  offline desktop use, upgrade/uninstall, and complete native regression are pending.
