# Repository maintenance

## What belongs in Git

Keep application source, tests, npm/Cargo lockfiles, Tauri configuration,
capabilities, native icons, documentation, and documentation assets. The shared
`.vscode/extensions.json` contains portable extension recommendations; personal
editor settings remain ignored. Solution files are eligible for tracking if a
future build needs them.

The source layout follows the existing boundaries: React rendering in
`src/components/`, lifecycle hooks in `src/hooks/`, typed IPC in `src/services/`,
and native feature modules in `src-tauri/src/`. Pure TypeScript matching/state
modules remain in `src/`; read-only native diagnostics remain in
`src-tauri/examples/`. No source renaming or architectural refactoring was needed.

## Build and tool caches

Use the [development instructions](../USER_GUIDE.md#development-and-release-build)
from the repository root. Keep `package-lock.json` and `src-tauri/Cargo.lock`;
use `npm ci` and locked Cargo builds. A first build needs dependency and tool
downloads. Offline builds require the corresponding caches to be populated.

`node_modules/`, Vite `dist/`, Cargo `target/`, and Tauri capability schemas are
generated and ignored. `src-tauri/gen/schemas/` is regenerated by Tauri; the
capability files referencing those schemas remain tracked. Do not ignore all
executables, DLLs, libraries, or `.cargo/` configuration: future intentional native
resources and reproducible build settings may need to be versioned.

Tauri manages WiX and NSIS in its platform cache. On Windows this workspace uses
`%LOCALAPPDATA%\tauri\`, including `WixTools314/`. The installed CLI's
`bundle.useLocalToolsDir` setting defaults to false; opting into it would cache
tools under Cargo's `target/.tauri/`. The NEXUS configuration retains the default.
The repository-root `WixTools314/` is a redundant extracted copy, not a configured
installer resource. Keep required tools in Tauri's cache when preparing offline
packaging. Preserve the tool distribution's license alongside any local copy.

## Local files and data

The ignore rules cover logs, temporary output, TypeScript build metadata, Windows
object/debug files, WiX intermediates, SQLite databases/sidecars, local environment
files, private-key containers, and agent backups. Reviewed `.env.example` files
can be committed; they must contain placeholders only. Ignoring a file does not
remove existing tracked copies or erase anything from Git history.

Existing local verification scripts, installer outputs, fixtures, and databases
remain under ignored `src-tauri/target/`. Root `stage-g-build*.log` files may
contain machine paths and stay ignored. The instruction backup under
`.token-optimizer-backups/` and empty `src-tauri/Finance_record.txt` are preserved
locally but excluded from the repository. They are not build inputs.

Do not bulk-delete ignored files: verification directories can contain fixtures
and isolated databases that are useful for repeat checks. `cargo clean` also
removes everything under Cargo's target directory. Inspect exact targets before
reclaiming space. Never include the production workflow database in cleanup;
follow the [backup procedure](../USER_GUIDE.md#workflow-data-and-backup).
